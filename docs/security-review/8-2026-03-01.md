### Separator Usage in Git Commands

**Critical Security Pattern:**
```python
# git_manager.py Line 189: Uses "--" separator
return self.repo.git.diff("--", *paths)

# git_manager.py Line 209: Uses "--" separator
self.repo.git.restore("--", *files)
```
- The `--` separator prevents filenames from being interpreted as git flags
- Example: Without `--`, a file named `-f` would be interpreted as a flag
- This is documented in security tests (lines 104-116 of test_git_security.py)

## Attack Vector Analysis

### 1. Command Injection via File Paths
**Attack**: Pass malicious paths like `; rm -rf /` to git commands
**Mitigation**: 
- GitPython library prevents command injection
- `validate_paths()` prevents `..`, absolute paths, and flag injection
- **Status**: ✅ PROTECTED

### 2. Path Traversal via JIRA ID
**Attack**: Use JIRA ID like `../../etc` to escape worktree
**Mitigation**:
- `validate_jira_id()` restricts to `[a-zA-Z0-9_-]+`
- **Status**: ✅ PROTECTED

### 3. Repository Root Access
**Attack**: Specify arbitrary repo_root to access system git repos
**Mitigation**:
- `validate_repo_root()` restricts to allowed base directories
- Defaults to current directory
- **Status**: ✅ PROTECTED

### 4. Flag Injection in Git Commands
**Attack**: Pass filenames starting with `-` to inject git flags
**Mitigation**:
- `validate_paths()` rejects paths starting with `-`
- Git commands use `--` separator
- **Status**: ✅ PROTECTED

### 5. Arbitrary File Access
**Attack**: Use absolute paths to read system files
**Mitigation**:
- `validate_paths()` rejects absolute paths
- All file operations restricted to repository
- **Status**: ✅ PROTECTED
